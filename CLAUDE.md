# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Setup

```bash
pip install basicsr facexlib gfpgan   # basicsr is the training/inference framework; facexlib+gfpgan are for --face_enhance
pip install -r requirements.txt
python setup.py develop               # required: generates realesrgan/version.py, which realesrgan/__init__.py imports
```

`realesrgan/version.py` is generated by `setup.py` from the `VERSION` file. Importing the package without an editable install fails.

## Architecture

### BasicSR registry — how training is wired

There is no training loop in this repo. `realesrgan/train.py` imports `realesrgan.archs/data/models` for their side effects, then hands off to basicsr's `train_pipeline`. Each subpackage's `__init__.py` globs its directory and imports every file matching a suffix — `*_arch.py`, `*_model.py`, `*_dataset.py` — and each class inside registers itself via `@ARCH_REGISTRY.register()` / `@MODEL_REGISTRY.register()` / `@DATASET_REGISTRY.register()`.

Consequence: a new component needs only a correctly-suffixed file plus the decorator. It is then selected purely by name from the YAML in `options/` (`model_type: RealESRGANModel`, `type: RealESRGANDataset`, `network_g: type: RRDBNet`). Names not found locally resolve against basicsr's registries — `RRDBNet`, the losses, and the SRGAN/SR base models all come from basicsr, not from here.

### Degradation pipeline is split across CPU and GPU

The high-order degradation model is deliberately cut in two:

- `realesrgan/data/realesrgan_dataset.py` (CPU dataloader) loads only the GT image and *generates blur kernels* (`kernel1`, `kernel2`, `sinc_kernel`). It never degrades the image.
- `realesrgan/models/realesr{gan,net}_model.py` `feed_data()` applies the actual two-stage pipeline on GPU tensors: blur → random resize → gaussian/poisson noise → JPEG, twice, then a final sinc filter with a randomized `[resize+sinc]`/`[JPEG]` ordering.

`_dequeue_and_enqueue()` maintains a training pair pool (`queue_size`, default 180) so a single batch is not stuck with one set of degradation parameters. All the `resize_prob`/`noise_range`/`jpeg_range` knobs live in the options YAML top section, not in code.

**`realesrnet_model.py` and `realesrgan_model.py` contain near-duplicate copies of this pipeline.** RealESRNet is the PSNR-oriented, GAN-free pretraining stage (`SRModel` base); RealESRGAN fine-tunes it with GAN + perceptual loss (`SRGANModel` base). Any change to degradation logic must be mirrored in both.

USM sharpening of the GT is applied per-loss, toggled by `l1_gt_usm` / `percep_gt_usm` / `gan_gt_usm` in the YAML.

### Inference is a separate code path

Inference does not touch the registry or basicsr's model classes at all. `RealESRGANer` in `realesrgan/utils.py` is a standalone helper: builds the network, loads weights, handles pre/mod padding, tiling, alpha channel, 16-bit input, and fp16.

- **Model selection is a hardcoded if/elif chain** in `inference_realesrgan.py` mapping `--model_name` → (network constructor, `netscale`, release URL). `inference_realesrgan_video.py` has its own copy. Adding a model means editing both.
- Weights auto-download from GitHub releases into `weights/` on first use (`load_file_from_url`).
- `--denoise_strength` for `realesr-general-x4v3` works via **DNI** (`RealESRGANer.dni`): it linearly blends the `-wdn-` and normal checkpoints' state dicts before loading. That's why `model_path` may be a 2-element list.
- `--tile` exists solely to avoid CUDA OOM; `tile_process()` splits, pads, upscales, and re-stitches.

Local architectures are only `SRVGGNetCompact` (the compact `realesr-*v3` models) and `UNetDiscriminatorSN`. `RRDBNet` (the `*plus` models) is imported from basicsr.

### Data prep scripts

`scripts/` are one-shot dataset preparation steps documented in `docs/Training.md`: `generate_multiscale_DF2K.py` → `extract_subimages.py` → `generate_meta_info.py`, producing the `meta_info` text file that `RealESRGANDataset` reads (one relative image path per line). `generate_meta_info_pairdata.py` is the paired-data variant for `realesrgan_paired_dataset.py` (used by `finetune_*_pairdata.yml`).

## Docker

`docker/` is tracked. Verified working end-to-end: builds, imports, and runs x4 inference on GPU.
See `docker/README.md` for the version-bump procedure and the four post-rebuild test commands.

```bash
./docker/build            # -> image real-esrgan:local; --no-cache / --pull supported
./docker/run              # interactive shell, repo bind-mounted at /Real-ESRGAN
./docker/jupyter          # JupyterLab on :8888, notebook-dir=/Real-ESRGAN, token printed on startup
DATASETS_DIR=/path/to/data ./docker/run     # default /mnt/c/DATASETS -> /Real-ESRGAN/DATASETS
DATASET_DIR=/path/to/data ./docker/jupyter  # default /mnt/c/temp -> /datasets; also read by run
```

Both `*_DIR` variables skip the mount with a warning when the directory is absent, and their names
differ by one `S` while mounting different paths.

Four constraints are baked into `docker/Dockerfile`; each one silently breaks the image if reverted:

- **Base must be `cuda12.8` or newer.** The `cu126` wheels build kernels only up to `sm_90`. On Blackwell (`sm_120`, RTX 50xx) `torch.cuda.is_available()` still returns `True`, then every kernel launch dies with `cudaErrorNoKernelImageForDevice`. Check with `torch.cuda.get_arch_list()`.
- **`ENV PIP_BREAK_SYSTEM_PACKAGES=1`.** The image's `python` is Ubuntu 24.04's system `python3.12`, marked PEP 668 externally-managed; PyTorch is merely COPY'd into `/usr/local/lib/python3.12`. Plain `pip install` fails with `externally-managed-environment`. A venv would additionally need `--system-site-packages` to see the prebuilt torch.
- **The `functional_tensor` sed.** `basicsr` and `facexlib` import `torchvision.transforms.functional_tensor`, removed in torchvision 0.17. Without the rename, `import basicsr` raises and every entry point is dead. The final `RUN python -c "from realesrgan import RealESRGANer..."` exists to catch this at build time.
- **No conda.** These PyTorch images have been conda-free since ~2.4 (Ubuntu 24.04 + Python 3.12, no `/opt/conda`). Any `conda` command fails with `not found`.

`docker/run` and `docker/jupyter` re-run `pip install --no-deps -e .` on startup because bind-mounting the repo over `/Real-ESRGAN` hides the `realesrgan/version.py` that `setup.py` generated at build time — it's gitignored, so it isn't on the host, and `import realesrgan` would fail immediately. It then chowns that file back to the host user so a later host-side `setup.py develop` isn't blocked by a root-owned file.

## Notes

- `cog_predict.py` / `cog.yaml` are the Replicate deployment wrapper and duplicate the model-selection logic a third time.
- `notebooks/test_Real_ESRGAN.ipynb` runs on both Colab and the container off two variables set in its first cell: `DST_DIR` (data) and `REAL_DIR` (parent of the repo). Every path is built from them, so keep new paths as f-strings rather than literals. `%cd` and `%%writefile` cannot interpolate them — use `os.chdir()` and `Path.write_text()`. `notebooks/test_Real_ESRGAN_docker.ipynb` is the container-only variant.
